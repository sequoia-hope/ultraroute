ultraroute

Building

A fast, GPU-capable, host-friendly KiCad autorouter, built on a fork of CopperRoute, and a bench for comparing routing approaches.

Where it stands

CopperRoute is cloned into copperroute/ on a local governance branch. It builds, and its benchmark harness runs against KiCad-refereed PCBench boards. The router now governs itself by default: it runs niced, uses at most half the cores, and stops gracefully at a memory ceiling while still writing the session. Routing goes through a pluggable RouterBackend trait. maze is the existing router; none is the scoring floor. A wgpu probe confirms the RTX 3060 is usable over Vulkan with 64-bit atomics. No GPU routing exists yet. Nothing has been pushed anywhere.

Median per-board speedup of governed over Java is 4.5×, but this includes roughly 3 s of JVM startup on every board. On the slowest boards the gap shrinks to about 0.8–1.7×. Governed and main produce identical results on every board. CopperRoute still loses 10 boards to Java on quality: 6 on unrouted count, the rest on score ties.

Route job: bluebuzz

Input is the tamed DSN route.py feeds Freerouting (bluebuzz 6c5bd5e): 6 layers with only 3 routable, 696 keepouts, and 38 connections open before routing. Every attempt is scored by the same copperroute drc against the bare input. Leaderboard (24 attempts), best recipe.

  • Withdrawn, being re-run: "nudge J4 by 0.5 mm → 17 unconnected". Moves left pins behind in the search tree, and the oracle and referee read the same stale geometry, so they agreed. Fixed, with a test that shapes move by exactly the vector. The corrected nudge runs are in progress
  • Best without moving parts: 18 unconnected, 0 new violations, 9 vias, 163.9 mm. Recipe: --set router.fanout.enabled=false, COPPERROUTE_OBSTACLE_HEURISTIC=1 and COPPERROUTE_REGION_HISTORY=0.25. Shortest copper: 153.7 mm with 10 vias (heuristic only)
  • Freerouting 2.4.1 governed: also 18, but 173 mm, 249 s, 1.3 GB. Freerouting master stalls past 600 s
  • Ripup history (factors 0.25–4): no effect. Bluebuzz's failures aren't nets fighting over space
  • Obstacle-aware heuristic: also 18. It's sharper in only about 1% of searches, but there by up to 11.6×
  • Fixed copper and keepouts never fully wall off a start on the routable layers, so the remaining 18 aren't impossible by geometry alone. Obstacle grid render. Retracted: an earlier "11 of 18 nets walled in" reading came from starts on the unroutable plane layers

Working

  • CopperRoute and Freerouting build locally
  • Benchmark harness with KiCad DRC referee on 42 PCBench boards
  • copper-governor: nice 10, RSS watchdog with soft stop and hard cancel, --nice and --max-memory
  • Default thread cap cut from cores−1 to cores/2
  • RouterBackend trait and --backend flag
  • PCB skill: governed-autorouter section in references/routing.md
  • wgpu 30 sees the RTX 3060 (Vulkan; int64 atomics, subgroups, timestamps)
  • Fork pushed: sequoia-hope/copperroute@governance; default job timeout now 30 min
  • tools/route_job.py: governed portfolio routing per board, keeps the best session and its recipe
  • Opt-in per-net ripup history (PathFinder history term), COPPERROUTE_RIPUP_HISTORY
  • Oracle fixed and made referee-consistent. (1) Pins now really move: the component moves before its items re-enter the search tree. (2) Clearance is judged like the DRC and KiCad, using each pad's net-class clearance, which on these boards is far larger than the pin's item class (0.152 vs 0.038 mm on DAC2020). Measured as real gaps. (3) Grandfathered pairs may not lose distance. (4) push(), settle's pressure: blocked parts shove free neighbours aside
  • --backend nudge: route, then try line-searched moves of parts with open connections on board clones, rerouting only what's open. A move is kept only if it closes more. 506 s on bluebuzz, so it needs tuning
  • Session reader applies placement (translation only), so nudged sessions are scored where the parts really are. Round-trip tested; unmoved sessions score identically
  • copper-morph move oracle, ported from settle (lean-jiggle): exact-shape clearance conflicts with grandfathering, guard band, bisection line search. Attached routable copper is ripped for the router; fixed copper pins the part. Independent DRC confirms moves on tomu-fpga add no violations
  • Opt-in obstacle-aware admissible heuristic (survey E1), COPPERROUTE_OBSTACLE_HEURISTIC: per-run coarse obstacle grid plus a backward Dijkstra per search, h = max(box, coarse), byte-identical when off
